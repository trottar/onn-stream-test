# D-123 — post-D5.4 TV EPG performance and guide UX follow-up

**Status:** active follow-up; performance diagnostic should precede production redesign

D5.4 is closed/runtime validated.

The final regression exposed three usability observations that are outside the
state-synchronization contract and should become the next bounded TV work.

## 1. Live TV / guide loading is very slow

Observed:

- many Live TV operations load slowly;
- guides and programme information can take substantial time.

Current Android EPG behavior can perform a companion guide request when the
local channel cache is not fresh/useful. The companion request path has a
30-second Android read timeout.

Do not guess at the bottleneck.

Next diagnostic should measure at least:

- TV-home/catalog load time;
- category-page construction time;
- local SQLite guide lookup time;
- companion `/plugins/epg/guide` request time;
- cache hit vs miss;
- programme persistence time;
- UI render time;
- number of guide requests generated by one user navigation action.

The output must retain raw per-stage timings so any classifier can be challenged.

## 2. `EPG mappings: 2` is misleading

`TvEpgRepository.stats().mappings` counts rows in the Android
`guide_mappings` fallback table.

That table is not the count of channels currently receiving guide data from the
Linux companion.

Companion-fed programme rows may be stored directly for many channels while the
fallback mapping count remains 2.

Therefore the current status label should not be interpreted as guide coverage.

Future diagnostics/UI should distinguish metrics such as:

- fallback guide mappings;
- channels with cached programme rows;
- channels with current/upcoming programmes;
- companion-backed channels refreshed successfully;
- total cached programmes.

## 3. Current guide UX is cumbersome

Product direction from runtime use:

Category views such as **Favorites** should behave more like a TV guide rather
than a plain channel list followed by a separate Program Guide action.

Target interaction direction:

- one row per channel;
- channel identity/logo/name;
- current programme title and time range;
- next programme when space permits;
- paging/virtualization so large channel groups remain cheap;
- selecting the row/channel plays the channel;
- long-press retains channel actions such as Favorite/Hide;
- guide data should be batched/prefetched for the visible page rather than
  forcing serial user-driven channel guide requests.

This is a UX/performance follow-up, not a reopening of D5.4 state ownership.

## Recommended order

1. performance timing probe;
2. correct/expand EPG status metrics;
3. design/implement paged guide-style category rows using the timing evidence;
4. runtime validate responsiveness and guide accuracy.

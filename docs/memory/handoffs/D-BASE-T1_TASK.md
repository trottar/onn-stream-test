**Piece 1 — onn thermals in the heartbeat and the session report.** On the client, once per 500 ms tick but read at most every 10 s: `PowerManager.getCurrentThermalStatus()` (API 29+, the 0-6 scale: NONE … SHUTDOWN) and `PowerManager.getThermalHeadroom(10)` (API 30+; returns NaN when unsupported — record NaN, do not fake it), plus a best-effort read of `/sys/class/thermal/thermal_zone*/temp` with each zone's `type`, keeping only zones that are readable without root (many Android TV boxes expose the SoC zone world-readable; if none are, say so — that is a finding, not a failure). Report: `thermal_status`, `thermal_headroom`, and `thermal_zones_c` (name → °C) in every heartbeat; in the session report, `thermal` block with status min/max/end, headroom min/max/end, each zone's start/min/max/end, and a per-minute series of the hottest zone (or headroom, if no zone is readable), capped at 240 entries. Register a `Thermal.OnThermalStatusChangedListener` for the session and count changes. Nothing else in the client changes.

**Piece 2 — a durable host sampler.** Turn S1/S2's ad-hoc sampler into `tools/host_resource_sampler.py`: every N seconds (default 30) append one JSON line with UTC time, `hwmon` temperatures by sensor name (`k10temp`, `amdgpu`, and any others present), GPU power if exposed, load average, and per-process CPU %, RSS, RssAnon, threads for RetroArch, the companion, the encoder and the FEC relay (found by command line, `ps -eo pid,cmd | awk` per TOOLS.md, never `pgrep -f`), to `logs/games/host_resource_samples.jsonl`, rotated at 4 MiB keep 3 under `logs/games/stream_log_archive/` using the same rotation helper as the heartbeat log, and covered by `tools/diagnostic_retention.py`. `--once` prints one sample and exits. The companion starts and stops it with each native stream session (subprocess, nice 10) so every future session has a host series without a harness; the sampler must never touch the hot path — if it fails to start, the session proceeds and `status` says so. Add `host_thermal_c` (hottest hwmon reading) to `native-stream-status` and to the decoder session log's host metadata so a report carries both ends' temperatures.

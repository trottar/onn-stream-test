## The loop, every task (`docs/ROADMAP.md` E3)

measured bottleneck → one narrow hypothesis → **one change, behind a
flag, reversible** → fresh benchmark on the frozen suite row at E2's
20-min window (`tools/e1_suite.py --e2`) → **accept or reject against
the bar pre-registered and hashed before any run**. The bar is never
changed after data. A task that cannot meet its precondition records
why and the queue goes on.

## Rules, every task

- Every rule of `QUEUE_2026-09-29B.md` and of E2-S1's teardown applies
  unchanged: adopted profile, 4x PS1 source and APK stay adopted; the
  companion through its unit only; one thing on the host at a time; Opal
  read-only; Code never runs `nft` or real `sudo`; the two-retry limit;
  ROMs / saves / savestates / keys / logs / APKs out of git; no
  addresses, MACs, SSIDs, ADB endpoints, serials, credentials or device
  identifiers anywhere; `h2_prep_redact.py --check` on every text file
  written; **nothing adopted; nothing committed.**
- **Each task's change lives behind its own `PRIVYHUB_*` flag; absent =
  today's behaviour, byte for byte.** The flag is set only inside the
  benchmark runs that need it and is **absent at every teardown and at
  the start of the next task**: the tasks do not compound. Adoption is
  the user's, afterwards, from the records.
- A **same-night control** run of the unchanged row is part of every
  task whose metric the link can move (loss, fps): the bar compares
  against the control, not only against E2's numbers.
- Preconditions checked before the task's first run: E2's final state
  (manager `PRIVYHUB_*` none; environ exactly
  `PRIVYHUB_ADAPTIVE_BITRATE_MODE=live`; no game; the adopted PS1 files
  byte-identical; APK `de072762…835e` CONFIRMED; flags absent). If a
  teardown cannot restore that state, **the queue stops there** and the
  record says why.
- If a benchmark run never reaches PLAYING or the change breaks the
  row, revert (unset the flag), record **REJECTED (broke the row)** and
  go on to the next task.
- Baseline commit: the user's E2-S1 commit (or `a56746e` if not yet
  made; say which in each record).

# H2-PREP task handoff — know the display path before the monitor goes

**Why.** `H2` (docs/memory/handoffs/D-BASE-H2_TASK.md) runs with the user present, the DisplayPort dummy plug installed and the monitor gone, and it will go badly if the first time anyone looks at how this host's desktop comes up is with no screen to look at. This task looks now, while the monitor is attached, and turns `H2` from a plan into a step list with the real connector name, the real mode list and the real persistence file already filled in. **Read-only: no `sudo` writes, no `xrandr --output` changes, no file under `/etc` created or edited, no reboot, no service enabled.** If a check needs root to read, record what it needed and move on.

**Inventory, each item recorded with the exact command and its output (trimmed to what matters):**

1. **Session type and display server.** `echo $XDG_SESSION_TYPE`, `loginctl list-sessions` and `loginctl show-session <id> -p Type -p Desktop -p State`, `systemctl status display-manager` (which DM, if any), whether the session auto-logs in (the DM's config file for autologin — read only), which user owns the X server, `ps -o pid,cmd -C Xorg,Xwayland,gnome-shell,kwin_x11,kwin_wayland`. `x11grab` needs an X11 session — if the session is Wayland with XWayland, state what the capture actually attaches to and whether that changes headless.
2. **Outputs and modes today.** `xrandr --verbose` (connector names, connected state, the current mode and rate, the preferred mode, every listed mode with its rate), `for c in /sys/class/drm/card*-*/; do echo $c; cat $c/status $c/enabled; done`, and `/sys/class/drm/card*-DP-*/modes`. Name the DP connector the monitor is on today, since the plug will take the same connector. Record the monitor's EDID vendor/model string only (no serial).
3. **GPU driver and headless behaviour.** `lspci -k | grep -A3 VGA`, the amdgpu module version, `cat /proc/cmdline` (any `video=` or `amdgpu.` parameter), and whether X is configured to keep running with no connected output (`/etc/X11/xorg.conf`, `/etc/X11/xorg.conf.d/*`, `/usr/share/X11/xorg.conf.d/*` — list them and quote any Monitor/Screen/Device section). State the two persistence routes for a forced 1920x1080@60 and which one this host's stack honours: (a) an `xorg.conf.d` file with `Section "Monitor"` / `Option "PreferredMode" "1920x1080"` for the named connector, and (b) the kernel parameter `video=<connector>:1920x1080@60e` — with the exact connector spelling each route needs (DRM uses `DP-1`, X uses `DisplayPort-0` on amdgpu; confirm both from the outputs above). Also whether the desktop environment has its own saved display configuration (`~/.config/monitors.xml` or equivalent) that would override an X config after login.
4. **What starts at boot and after login.** `systemctl list-unit-files --state=enabled | grep -i -E 'ssh|display|getty|companion|privyhub|retroarch'`, `systemctl --user list-unit-files --state=enabled`, `~/.config/autostart/*`, `crontab -l`, and whether `tmux` sessions survive logout (`loginctl show-user $USER -p Linger`). State plainly how the companion is started today (by hand in a tmux pane, per TOOLS.md) and what an unattended power cycle would leave running — nothing, if that is the answer.
5. **The SSH console, read-only.** `systemctl is-enabled ssh` / `sshd`, `sshd -T 2>/dev/null | grep -i -E 'passwordauth|pubkeyauth|permitroot'` if readable, and whether a listening SSH port exists (`ss -tln` — port number only, no addresses in the record). `H1` is the user's own step; this only tells them whether it is already done.
6. **Capture geometry today.** From the last `native-stream-status` and `logs/games/native_video_alpha.log`: the `x11grab` display, window id source, the source width/height and the scale/pad filter, so `H2` can compare byte-for-byte.
7. **ADB after a reboot.** From TOOLS.md and the launcher code: what the onn needs after the host reboots (re-pair, re-approve the key, the companion address) — list it so the user is not surprised at the TV.

**Output.** docs/memory/evidence/H2_PREP_HOST_DISPLAY_INVENTORY_<date>.md with the raw outputs (trimmed, redacted) and SHA-256s of any saved command outputs under evidence/h2_prep_<date>/. Then **rewrite docs/memory/handoffs/D-BASE-H2_TASK.md** in place — keep its gate, its five checks and its record section — filling in: the connector name in both spellings, the exact `xrandr --output … --mode 1920x1080 --rate 60` line, the exact persistence file path and contents for the route this stack honours (as a block the user pastes, marked as the one write H2 makes), the boot-order facts from item 4, and a "before you unplug the monitor" checklist (SSH reachable from the PC per PLAN_WEEK, tmux alive, companion command known, the plug's expected modes). Add a short note to CURRENT.md's Next Action and the dated memory file; MEMORY.md gets one durable line (session type, connector, persistence route) only. Nothing else in memory changes. Never retry a failing command more than twice. No addresses, MACs, SSIDs, serials or device identifiers in any memory or evidence file.

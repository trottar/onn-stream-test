## B102 — the end-screen learner (`tools/h7_endscreen.py`)

- **Learn (hashed design):** input — a folder of runs (frames + `index.csv`) and a labels file (classes by time range; `ignore` left out). Every frame reduced to a small grey picture (the size stated and tested, e.g. 160 wide). From the labelled frames alone the tool finds: **the screen mask** — the pixels that are steady across all frames of the "screen" classes (every class but `other`) taken together; **the outcome mask** — the pixels steady within each screen class and different between them; and each class's **reference** (its mean over the outcome mask). A frame is read as: is it the screen (distance over the screen mask under a learned threshold) → which class (the nearest reference over the outcome mask, with a margin to the second nearest) → else `other`. The thresholds are learned with a stated safety margin from the gaps the labelled frames leave. **The output is a spec** — a small JSON plus the masks and references as arrays in one file beside it (not pictures) — and **a learn report**: frames per class, the masks' sizes (pixels and share of the picture), per class the worst own-distance against the best foreign distance (the gap), and a plain verdict per class: separable / not separable from these frames.
- **Read:** `read(frame) → {"screen": bool, "class": … | "other", "distances", "margin"}`; **`ended` needs K agreeing reads in a row** (K stated; at one read a second) so a single odd frame never ends a game; a screen seen with no class close enough → `"class": "unknown"` (e.g. a draw never shown) — reported, never guessed.
- **Score:** `score(folder, labels, spec)` → the confusion counts per class and **the number of `other` frames read as a screen (must be 0)**.
- **On T88's real frames (read-only; numbers only in the record):** learn on the first half of each labelled range, score on the second half and on every `other` frame; the counts; the gaps; whether `start`, `end_P1`, `end_P2` are told apart; the masks' sizes; the time to learn and the time to read one frame on the hub (it must be milliseconds). Then the same with the frames **shifted by a few pixels and rescaled by a few percent** (made in memory) to see how much the reading depends on exact alignment — the stream's capture will not line up exactly with a screenshot; the numbers, and the alignment the tool can absorb (a small search over shifts and scales, if you build one, stated and timed).
- **Tests (synthetic pictures drawn in the tests):** a "screen" with a still panel, a moving banner and a varying portrait; two outcomes differing in one digit-like patch; `other` frames of moving shapes — the masks exclude the moving and varying parts; the classes are told apart; an unseen third outcome reads `unknown`; an `other` frame never reads as the screen; K-in-a-row; a labels file naming a class with no frames → a plain error; nothing but the image library needed.
- Record `evidence/B102_H7_END_SCREEN_LEARNER_2026-11-12.md` + dir; patch.

# D-BASE-P3 task handoff — is the loss a burst-overflow? Pace the sender and see

**The question, from `B2` and `R3a`:** on the production path loss is still bursty (median 4.46 packets per gap event, max forward gap 8-32 packets) and a 3 s encoder stall's resume burst (~2,600 packets in 2 s) dropped 690 packets with no restart — packets minted and lost between the host socket and the onn decoder. The encoder emits each frame's packets back-to-back at line rate (an IDR at 7 Mbps / GOP 15 is tens of packets in a few hundred microseconds), so every frame is a micro-burst into the Opal's wireless queue and the onn's receive buffer. If the ordinary loss is that queue overflowing on the larger frames, spreading each frame's packets across part of the frame interval will cut loss and burst size sharply; if the loss is air (interference, retries), pacing will change nothing. Interleaving the two arms within one run removes the time-of-day confound that left `B2` indeterminate.

## Wireless ADB stale-cache recovery regression

The C2 Android install exposed an untested D-053 failure branch: a stale private
cached `_adb-tls-connect._tcp` target caused `adb get-state` to emit
device-not-found, which PowerShell promoted to a terminating
`NativeCommandError` under script-wide `ErrorActionPreference=Stop`.

The existing recovery sequence was therefore aborted before connect/mDNS/
reconnect/server-restart recovery could run.

Development fix: route all exploratory ADB recovery commands through one
fail-soft wrapper that captures/suppresses native errors and returns explicit
exit/output state. Final recovered-device validation/install/launch remain
fail-hard.

The earlier D-054 `ADB_TARGET_ALREADY_ONLINE` result did not exercise this stale
cached-target branch. Runtime validation of this fix is pending.

C2 candidate source remains intentionally unchanged.

## Remote-foundation architecture and roadmap promotion

The synchronized C1.1/privacy checkpoint is the clean predecessor for this
documentation-only architecture update.

Accepted correction:

- ordinary household router/Wi-Fi is upstream only;
- home Opal is the PrivyHub network/trust domain;
- future Linux hub and PrivyHub/IoT devices live behind the Opal;
- future travel GL-iNet-class router provides a portable trusted client LAN;
- secure overlay and PrivyHub application authorization are separate layers;
- Tailscale is the preferred first provider candidate, not a permanent
  dependency;
- source/request IP is not durable client identity;
- no permanent travel-router model is selected yet.

Phase C remains active. Its profiles, telemetry, adaptation/FEC behavior and
streaming boundaries must be reusable for future WAN work, while WAN overlay,
authentication and travel-router implementation remain deferred to Phase G.

queue/buffer growth creates runaway latency.

future WAN experiments once video, 8+1 parity, PCM16 stereo audio and
packet/tunnel overhead are considered. This does not change the stable PCM audio
path.

- G — Secure Remote Access / Portable Client Foundation;

- I — Home Infrastructure / Broader Plugin Expansion;
- J — Local Intelligence / Voice / Privacy-Aware AI.

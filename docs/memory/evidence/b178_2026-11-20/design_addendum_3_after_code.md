# B178 — third addendum after code: which save the label stage names (found by the misread table)

The hashed design (section 2) named every save whose check failed. On the made-up titles one misread label spoils
the other saves' left-out readers too. With 24-14 given for 21-14, the line named that save, and also the three right
saves, which the readers learnt with the bad label could not read. With 16-2 given for 15-2 (T90's shape) and one
more save, a right save read 36-28 for 35-28. A session told to read right saves again re-reads them; named twice, the
user would be asked about saves that were right.

**As built (the cells unchanged, every one still shown):**
- **The line names first the saves a reader learnt without them contradicts** (it reads other numbers).
- **When several are contradicted**, it names the one whose reading, replaced by what the others' reader read, lets
  every other contradicted save read back as labelled. When no single save does that, all of them are named.
- **A save that is merely not read** (no digit only it shows) is named only when no save is named for anything else.

On the table every misread names exactly the misread save (`table.txt`).

## 0. Settled

1. **The core: Mupen64Plus-Next first; it must be fetched.**
   - The RetroArch AppImage (1.22.2) bundles no core: its squashfs, listed with `7z l` and nothing run, has 123
     files and no `*_libretro.so`.
   - The cores folder has no N64 core. The AppImage home holds only core-info files.
   - **`tools/n64_core_check.py` on the hub: `"state": "fetch needed"`, exit 3.**
   - Mupen64Plus-Next is the maintained core. GLideN64 is hardware GL on the Vega 7, and RetroArch here already runs
     the default GL driver. Its own info file calls it the first choice over ParaLLEl-N64.
   - ParaLLEl-N64 is kept by name only (`PRIVYHUB_N64_CORE=parallel_n64`; no options written for it). Its Vulkan
     ParaLLEl-RDP costs more than the hub has shown it can spare.
   - Neither core is present, so neither was measured.
   - **The fetch is A's, with the user's go:**
     - the per-core zip from the libretro buildbot. Look under `stable/1.22.2/linux/x86_64/` first; otherwise use
       E3-S4's precedent, `nightly/linux/x86_64/latest/mupen64plus_next_libretro.so.zip`;
     - unzip it into `cores-linux/`, recording the zip's and the `.so`'s sha256;
     - then run `n64_core_check.py --keys`.
2. **The system listed in place.**
   - **The drive:** the N64 folder beside the PS2 one holds 13 `.v64` files, with no subfolder and no stem in two
     formats (counted by extension only). It is read-only for the hub's user.
   - **The list:** from the folder that **`N64_DIR=`** names in the gitignored paths file (PS2's file; one line for A
     to add at stage 1). The new `companion/inplace_library.py` is B49's listing generalised to "a system → a key
     of that file".
   - **The rules:** `.z64` > `.v64` > `.n64`, one entry per stem, hidden names skipped, no `mkdir`.
   - **PS2's listing** is not moved onto it.
3. **The pad** (Mupen64Plus-Next's defaults, **recalled**; the user's C21 line reads them back):

   | N64 | the onn's pad |
   | --- | --- |
   | the analog stick | the left stick |
   | A | A / Cross (south) |
   | B | X / Square (west) |
   | **C-buttons** | **the right stick** (up / down / left / right) |
   | Z | the left trigger |
   | L / R | the bumpers |
   | Start | Start |
   | D-pad | D-pad |

   - The core is recalled to make the face buttons C-buttons while R2 is held.
   - **The alternative, stated and not chosen:** the C-buttons on the face buttons (the core's "independent
     C-button" option, which moves A / B too). That is B61, if the user asks.
   - **The form:** core options, no remap file. `privyhub-input.cfg` has `analog_dpad_mode "0"` for players 1-4,
     so the stick stays analog, never a D-pad.
4. **Four ports, always.**
   - Every N64 launch passes `--device=1:1` … `--device=4:1`, whatever `players_joined` / `players_chosen` say.
   - `ports_set` reads players 4, `multitap` false, `multitap_available` false. The client's hold-to-join (read,
     unchanged) therefore fills P1-P4 on the existing ports and **never asks for a relaunch: no "Setting up 4
     players…" on N64.**
   - **The cost, disclosed:** the core sees four controllers, each with a memory pak.
5. **Save states and the recovery stack: RetroArch's, as PS1's, no skip.**
   - SAVE / LOAD (slots 1-3), the hold's slot-9 scratch, the stall resume and the give-up save all work with no
     system check.
   - **The rewind:** `PRIVYHUB_INPUT_HOLD_REWIND=1` is B12's `state` mode, so no RetroArch rewind for any core. N64's
     state size is recalled at the order of Beetle's 16 MB; A reads it at C22. RetroArch's own rewind would cost as
     Beetle's did and stays off.
6. **The core options and the frame rate.**
   - **The `.opt`:** the per-core `~/.config/retroarch/config/Mupen64Plus-Next/Mupen64Plus-Next.opt`, merged at
     launch (other lines kept). The keys are recalled; `--keys` checks them on the fetched `.so`, and a wrong one is
     inert:
     - GLideN64, HLE RSP, the dynarec;
     - **native resolution** (`EnableNativeResFactor 1`, 320×240, 4:3);
     - `Framerate Original`;
     - `alt-map False`;
     - a memory pak on ports 1-4.
   - **No audio option:** RetroArch resamples to 48 kHz as for every core.
   - **The stream** captures at a fixed 60 (`-r 60`, adopted), so a title drawing 20-30 frames reads 60 on the
     heartbeats. **UX-R3's R rule never fires on it and does not see its own slowdowns.**
   - **Hence `tools/n64_frames.py`:**
     - distinct frames per second from a showinfo capture;
     - the title's internal rate (the mode, snapped to 20 / 30 / 60);
     - a hitch second below 5/6 of that rate;
     - the hitch rate per 10 min, beside UX-R3's and PS1's.

# A9 first runtime pass — product gap discovered

The first A9 runtime pass returned `PHASE_A_A9_EMULATOR_REGRESSION_NOT_CONFIRMED`.

Most regression surfaces passed: SNES, ordinary PS1 2P/controller-profile behavior, frozen preview, Save/Load, resume, host coexistence, cheat launch/effect, IPS mod launch/effect, custom A8 profile mapping, End teardown, final four-player evidence preservation, repository HEAD, and `git diff --check`.

Two A9 measurements were probe-detection misses rather than reported gameplay failures: NES and Genesis were both reported as `<unknown>` even though the user separately marked direct launch, gameplay, analog-to-D-pad, coexistence, End, and XInput teardown as normal.

A real product gap was discovered in CTR: its battle mode still showed Players 3/4 greyed out because the first PS1 multitap implementation was intentionally configured only for Crash Bash. The user chose a maximum product scope of four local players and explicitly rejected exposing Port-2 multitap because it can disturb this topology.

Active design: a per-game PS1 `Multitap: On/Off` control, parallel to the existing PS1 controller selector. `On` means Beetle PSX HW Port 1 enabled and Port 2 forced disabled. A metadata checker may recommend On for PS1 titles with more than two local players, but recommendations must not silently enable multitap. Unknown titles fail closed to Off.

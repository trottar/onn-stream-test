## 1. A's audio wait (H3-P2's in-run change): KEPT, narrowed

- **PCSX2's startup order**, from its own log (seconds since its start):
  - the swap chain 1.41;
  - **`Creating Cubeb audio stream` 1.45**;
  - `VM subsystems initialized` 1.54, then PINE's first answer;
  - the pads 1.56.
- The game logs agree: the sink-input came 0.1-0.3 s after the window, the hotkey pause ~0.14 s after it; the failed
  launch froze PCSX2 at 1.6 s with PINE not yet answering.
- **The earliest signal that guarantees the audio stream is the sink-input itself.** PINE comes later, so it is never
  earlier. A's wait stays, ≤ 45 s, then the paused handoff.
- **Narrowed:**
  - it runs on the session's injectable `run` / `sleep` / `clock` (`Session.wait_audio`) and polls every 0.1 s;
  - the first pause waits ≤ 1.0 s for PINE's first answer before choosing SIGSTOP.
- **The game log** gains `PS2 audio: sink-input <s>s|none` (A's line) and `PS2 memcards: …`.
- **PINE vs. the wait, separated** (a fake PCSX2 timeline: the window, then the stream 0.3 s later only if running,
  then PINE 0.1 s later):
  - the wait + PINE late → **hotkey**, the audio present;
  - the wait + PINE never → **SIGSTOP after the stream exists**;
  - the wait alone (no PINE poll) → SIGSTOP after the stream: A's change alone already fixes the defect;
  - **B49 (no wait, no poll) + PINE late → SIGSTOP before the stream, no sink-input ever: the defect reproduced**;
  - the wait is bounded at 45 s.

## 2. The memory cards: formatted by the companion

- **Found:** the hub's cards are 8,650,752 bytes, all `0xFF` (PCSX2: `[8 MB, UNFORMATTED]`). PCSX2 2.8.2 has no CLI or
  ini way to create a formatted card (only its Qt dialog).
- **So `companion/ps2_memcard.py` (new) formats one** at a PS2 launch, for each slot's card that is absent or all
  `0xFF`. A card with any other byte is **never touched**.
- **The layout:**
  - the superblock: `Sony PS2 Memory Card Format `, the version 1, 2, 0, 0 dotted, 512 / 2 / 16, 8192 clusters, offset 41, end 8135,
    backups 1023 / 1022, indirect FAT `[8]`, type 2, flags `0x52`;
  - the indirect FAT → FAT clusters 9-40;
  - the root `.` / `..`;
  - ECC on every written page.
- **The ECC is PCSX2's own:** both 256-byte tables in its 2.8.2 binary (right after its copy of the card magic) equal
  the formula used (`ecc_table_check.txt`). A Hamming-property test (a lone odd byte located by the line parities)
  guards it independently.
- **A checker** (`ps2_memcard.check`) reads a card back: size, magic, every superblock field, the IFC → FAT chain, the
  root entries, every page's ECC.
- **The ini:** `[MemoryCards] Slot1_Enable = true`, `Slot1_Filename = Mcd001.ps2`, and slot 2 the same with
  `Mcd002.ps2`.
- **Recalled, checked by PCSX2 at A's HOME-4+:** the superblock values and the 4 spare padding bytes. The pass is
  PCSX2's boot line `[8 MB, Formatted]` and a save in play (C12).
- The hub's two cards are formatted at A's first PS2 launch after the companion restart (they are all `0xFF` now;
  nothing to lose).

## 3. The frame tears

- **The source:**
  - the ini had `VsyncEnable = false` (Vulkan IMMEDIATE);
  - the hub's `xfwm4` composites but **unredirects fullscreen windows** (`unredirect_overlays` true), so PCSX2 presents
    straight to the scanout, mid-frame;
  - `x11grab` copies whatever the front buffer holds;
  - RetroArch sessions run with `video_vsync = "true"` and showed none.
- **Set:** `VsyncEnable = true`, `DisableMailboxPresentation = false`. This gives MAILBOX where the driver offers it
  (tear-free, no wait), else FIFO.
- **The trade-off, only under FIFO:** up to one frame (~17 ms) more latency, and a 59.94-Hz game on the 60-Hz display
  repeats a frame about every 17 s. A reads frame-time p95 (H3-P2: 16.7 ms) and the user's feel.
- The desktop's `xfwm4` settings are not changed.

## 4. The bindings

- PCSX2 2.8.2 uses SDL3 names. Its log rejected only `SDL-k/A` / `B` / `X` / `Y`, and its binary carries `FaceSouth` /
  `FaceEast` / `FaceWest` / `FaceNorth`.
- **Cross / Circle / Square / Triangle = FaceSouth / FaceEast / FaceWest / FaceNorth;** the other 20 names were already
  accepted.
- **The accepted set** (recorded, a test checks every binding of Pad1-Pad4 for 1 / 2 / 4 players): `FaceSouth FaceEast
  FaceWest FaceNorth Back Guide Start LeftStick RightStick LeftShoulder RightShoulder DPadUp DPadDown DPadLeft DPadRight`
  and `±LeftX ±LeftY ±RightX ±RightY ±LeftTrigger ±RightTrigger`.
- The log also confirms SDL-0..3 = P1-P4 (player ids 0-3 in creation order).

## 5. The keeper's PS2 label

- **The cause:** `diag_read` takes a session's core from the game logs' names, and the PS2 log (`…-ps2.log`, no id) did
  not match, so a PS2 session inherited the previous PS1 launch.
- **Now:**
  - a `-ps2.log` is a launch with core `pcsx2`;
  - the recovery log's `ps2_session` row just before a `session_started` (≤ 120 s) marks the session PS2, and it wins;
  - a PS2 row carries `system: "ps2"`, `title` `PS2`, `core` `pcsx2` (other rows byte-equal);
  - `Analysis.ps1_reference(rows)` excludes PS2;
  - the keeper's copier (`trip_log_keeper.GAME_LOG`) now copies `-ps2.log` too;
  - `diag_check` prints a seventh line, `last session: ps2 (pcsx2) <end>, hitch s / 10 min <n>`, only when the
    newest `sessions.jsonl` row is PS2.

## 6. P2's capture time (`tools/ps2_p2_window.py`, new)

- **`plan`:** the earliest second that is ≥ 60 s after the last `session_started` and not within 90 s of any pause
  (`session_ended`, or the PS2 log's `PS2 pause:` lines), over the 60-s capture. Minute 3 is preferred; the fallback
  is minute 3 (`fallback: true`) if nothing is valid before minute 9.
- **`check --start <UTC>`:** after the capture, valid only with no pause in that span (P7f's case → retake).

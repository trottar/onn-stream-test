## B198 — `register --max-score N` (score only)

- **register:** `--max-score N`, a whole number 1-9999, only with `--result score` (else a usage error). One cell,
  "the highest score one side reaches (--max-score)". Kept in the binding as `max_score`. The inputs digest gains it
  only when given, so T90's kept verdicts stay as they are; a changed N runs label, learn and bench again. A register
  run without it drops it.
- **learn:** the every-digit cell needs **the digits a number 0..N can show** (N = 4: 0-4; N = 5: 0-5; N ≥ 9: all
  ten), each learnt as today (two saves, or one save several times by B186's rule). Line-score cells are never above
  their final (they add up to it), so the same digits serve both. The cell is named for N ("every digit that can occur
  up to 5 (0, 1, 2, 3, 4, 5) …"). Its read adds **"not expected (above the highest score)"**: the other digits,
  recorded, never a cell. `recorded` adds the expected and not-expected digits, and any end save with a number above
  N (recorded only).
- **The line for one more save** names only expected digits: "… whose final score shows 5 (either side's number) …
  1 digit is still short (5) …".
- **The spec carries N** (`score.max_score`); its reuse key gains N when given.
- **At the hub** (`h7_endscreen.ReaderScore`): a final above N, every digit read, → `unknown` with `end_unread` and
  `above_max`. A digit never learnt has no template and was already `unknown` with `end_unread` (B178). Either way,
  B182's watch gives up after K such reads: `final_unreadable`, no scores, no winner. `companion/` is unchanged; the
  running companion reads `max_score` only after its next start (session A's bench restarts it).
- **Without the flag: today** — the same inputs digest, cell name, read and spec (`Low.test_3`, `Register.test_2`).

**How often a match is given up, in plain words:** once learn passes, every digit 0..N is learnt, so the hub gives
up only on a match where a side ends above N — **as often as your matches end above the number you name.** For T92 the
user says a short match ends 2-1 or 3-0, rarely more. Named 5, that is almost never. Named 3, a match where a side
scores 4 or more is given up. A match given up shows no winner, and the board counts it as a draw (the PC side's note
of 2026-11-20: nobody wins, half the winner's coins each).

**The other side of N:** learn still needs every digit 0..N shown by two saves. A title whose screen shows only its
two finals shows two digits a save, so N = 5 needs at least six end saves, with a 4 and a 5 each in two of them. If
matches rarely pass 3, those are hard to get. **A lower N asks for fewer digits and gives up more matches.**

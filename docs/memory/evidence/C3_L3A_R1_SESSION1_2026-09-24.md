## The probe change

1. **Split-session finalize.** When no one session reaches the expected
   SSRC count, `--finalize` takes the sessions posted after the run's
   start (the run id's local time, zone from `generated`) and before now,
   not in `decoder_sessions_before`, in order of arrival, until their
   `ssrc_changes` reach the expected count, and uses them only if the sum
   is **exact**. `--decoder` now takes several files, with the same sum
   check. Each session takes the next `ssrc_changes` expected transitions
   and is aligned on its own Phase-A fires (spread ≤ 1 s each; a session
   with no Phase-A fire aligns on its v2 park / restore fire times); each
   mark is checked in the session whose span holds it. The report gains a
   **CLIENT RESTARTS** section (the first session's end and the next one's
   start on the probe clock, marks in the gap, marks within W after it),
   a `sess` column in the per-transition and per-mark tables, and both
   sessions' close-out rows side by side. If the sum does not match, the
   report says which count it found against which it expected and skips
   the decoder axis as before.
2. **Keep the state.** Every run also writes
   `logs/streaming/c3_l3a_runs/states/<run_id>_state.json` (outside
   `--aggregate`'s `*.json` glob). `--finalize` without `--state` uses the
   newest copy when the shared state file holds a different, older run.
   This run's state was byte-copied there before the re-finalize (SHA-256
   `4cf4f264…6abc`, the same as the shared file).

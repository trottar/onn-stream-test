## Built (`b158.diff`, `companion/party_minigame.py`)

`_winner_entry`: a sidecar's `"result": "winner"` (no `scores`, no `places_to_scores`, 2-4 players) with a version-2
spec whose end classes are exactly `end_P1`…`end_Pn` (`end_Pk` → port k won; the scores built one-hot), or a version-3

another word, or with `scores` / `places_to_scores`: not listed. No `result`: today, row for row.

2" — by the design's own rule, port 2 is seat 1: scores [0, 1], winner 1; the tests follow the rule.

## The board's side (read only; nothing changed there)

`hub_minigame.gd` passes the hub's scores through; `rules/game.gd` turns them into places (`_places_from`: a player's
place = the number with a strictly higher score; ties share the better place) and pays `minigame_payout[place]`,
`[10, 5, 2, 0]` by default (`rules/game_config.gd`; the classic and friendly sets the same). **Scores [1, 0, 0, 0] →
places [0, 1, 1, 1] → coins [10, 5, 5, 5]** and one mini game won for the winner: the three losers get 15 between them
against 7 for a full order. **For the PC side:** a winner-only result wants its own payout — the tied last taking the
worst place, or a winner-only row such as `[10, 0, 0, 0]`; the hub cannot say "tied last" through the scores alone.

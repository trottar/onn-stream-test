## The rule

`--aggregate` pools a run file only if its analysis records **state schema
`privyhub_c3_l3a_gameplay_acceptance_v2`** and **config = the
pre-registration** (`PREREGISTERED_CONFIG`): `traversals` 10, `dwell_min_s`
55, `dwell_max_s` 90, `window_s` 5.0, `ramp_gap_s` 4.0, `park_seconds` 45.
Every run file found is listed in the report's `=== POOL ===` section under
POOLED or SKIPPED with its reasons (schema, and each config field that
differs, with its value and the pre-registered one); the same listing goes
to stdout and to the aggregate JSON (`files`, `pool_rule`). The pooled
table keeps P2R1's per-window scoring. **`--pool-all`** (default off) also
pools v2-analysis runs outside the pre-registration; the report title gains
" - POOL-ALL OVERRIDE" and the first line under the header is a WARNING
(the `Classification:` header block itself is unchanged — it is
load-bearing). With nothing pooled the report says so and exits 0 without a
traceback. The CLI defaults now read from the same constant, so the rerun
command and the pool rule cannot drift apart.

Why P2R1's skip failed: it keyed on the *analysis* schema, and P2R1's own
re-finalize wrote the 2026-09-20 file as analysis `_v2` from a `_v1` state
(`C3_L3A_P2R2_SMOKE_SESSION_2026-09-24.md`).

Cosmetic, since the file was open: a blank line is printed before the
rating anchors, and one after the rating answer, so a teed run log shows
the y/N question, the anchors and the rating prompt each on its own lines
(an answer typed at `input()` is not echoed into a teed log). The task
named only the first; without the second the next question would still
land on the rating prompt's line. The prompt and anchor text are
byte-identical. **Not exercised** — it is on the interactive run path, and
no session was run.

## 0. Settled (the code)

**The player.** `MainActivity.playMedia` builds a Media3 `ExoPlayer` with `DefaultHttpDataSource`, or the identity
factory over it.
- On `onPlayerError` it does four things: saves progress, marks the source failed (TV health or IPTV "recently
  failed"), sets the status text "Playback error…", and stops. It never retries.
- **There is no Retry button today.** The only "Retry" in MainActivity is the TV guide dialog's. B35 adds one under the
  flag only.

**The range server.** `companion/range_server.py` is a `ThreadingHTTPServer` subprocess of the service and inherits
the service's environment.
- A client's reset propagates out of `copyfile`. `socketserver`'s `handle_error` then prints a traceback with no
  timestamp and no Range: that is TRIP-R2 §4's unreadable record.
- Its access lines go to the range-server log without Range or bytes.

## 1. Built (`b35.diff`)

### The client: `debug.privyhub.vod_retry=1`

Only exactly `1` after trim turns it on. Absent, empty, `0` and junk are off.

**`vod/VodRetry.kt` (new, pure Kotlin):**
- `VodRetryFlag`: the property, read by reflection.
- `VodRetryPolicy`:
  - **backoff 1, 2, 4, 8, 15 s, then 15 s each**, so attempts come at +1, +3, +7, +15, +30, +45 … +150 s;
  - **bound 150 s** from the episode's first error, inclusive (13 attempts);
  - **retryable:** 1003 timeout and IO 2000 / 2001 / 2002 / 2004 (unspecified, connection failed, connection
    timeout, bad HTTP status);
  - **not retryable:** content type, not found, no permission, cleartext, position out of range, and every decoder,
    parser or DRM code. Those take today's path at once.
- `VodRetryController`:
  - **The position is the first error's**, kept through the failed attempts.
  - Each scheduled attempt is `retryAt(position)`: `seekTo`, `prepare`, `playWhenReady` on the same player and item.
    That is a new connection with a Range from the position.
  - **READY closes the episode** with `vod_resumed`.
  - **Past the bound** it writes `vod_gave_up`, returns false so today's branch runs ("Playback error…", the failure
    mark), then offers **Retry**.
  - **Retry** starts a new episode at the position.
  - `cancel()` drops the pending attempt.

**`vod/VodRetryAndroid.kt` (new):**
- the main-thread scheduler;
- a small **"reconnecting…"** mark, top-end on `PlayerView`'s overlay frame;
- the Retry dialog ("Playback error" / "The connection to the hub was lost." / Retry / Close);
- **the rows:** `POST /diagnostics/vod-client` (JSON, the session header as every control call, 1.5-s timeouts, each
  failure ignored), from a daemon thread.

**The rows** are `vod_error`, `vod_retry` (attempt, delay, elapsed), `vod_resumed` (attempts, elapsed) and
`vod_gave_up`.
- Each carries `media`, `position_ms`, `bound_ms`, and `error_code` / `error_name` where relevant.
- `media` is 12 hex of a sha256 over the source id. `error_name` is Media3's code name, **never the message**, which
  can carry a URL. **No title, path or URL is in any row.**

**`MainActivity.kt`: five small hunks plus three imports, every one a `vodRetry?.` call on a field that is null unless
the flag reads `1` and the item is not live.**
- (1) the field;
- (2) the build in `playMedia`, after `releasePlayer`;
- (3) in `onPlayerError`, after today's `saveCurrentProgress()` (the save still happens),
  `if (vodRetry?.onError(...) == true) return`, and `vodRetry?.afterTodaysError()` after today's branch;
- (4) `vodRetry?.onReady()` at `STATE_READY`;
- (5) `vodRetry?.cancel(); vodRetry = null` first in `releasePlayer`.

With the field null, Kotlin's safe call evaluates no argument: `exoPlayer.currentPosition` is not read.

### The host: `PRIVYHUB_VOD_LOG=1`

Only exactly `1` turns it on. This is one new line for both host pieces, since the range server inherits the
service's environment.

**`companion/vod_log.py` (new):**
- **`RangeLog.install(handler_class)`** wraps the handler on the class: `send_response` (the status), `send_header`
  (`Content-Length`), `copyfile` (a counting writer) and `do_GET` / `do_HEAD`.
- It writes **one row per request** to `logs/vod_range.jsonl` (rotating, 5 MB × 3). The row holds:
  - `at_utc` / `end_utc` (ms), `method`;
  - `id`: 12 hex over the URL path, with the query and so the media token dropped first;
  - `kind` (`vod` / `media`), `range` (the header if `bytes=N-M`, else `invalid`);
  - `status`, `length`, **`bytes`** (actually written), `duration_ms`;
  - **`closed`**: `complete` / `short` / `client_reset` / `broken_pipe` / `error` (with the class name) / `no_body`.
- **The exception is re-raised,** so today's traceback still reaches the range-server log.
- **`ClientLog.accept`** takes the client's four rows. Each field is whitelisted (ints; `media` 12 hex; `error_name`
  `[A-Z0-9_]`). Anything else is rejected with 400. It writes `logs/vod_client.jsonl` with `at_utc`.

**`range_server.py`:** `VOD_LOG = None` and one guarded block after the class (the import and `install`). **The class
body is not edited.**
- The design placed the import beside `RANGE_GATE`'s. It sits after the class because `install` needs the class; it
  is the same single guarded block.

**`privyhub_service.py`:**
- one guarded import block beside G5-S1's: `VOD_CLIENT_LOG = None`;
- one `do_POST` branch before `/diagnostics/client-health`:
  `if (_vod_client_log := globals().get("VOD_CLIENT_LOG")) is not None and request_path == "/diagnostics/vod-client":`.
  - **The global is looked up, not named** (B1's gate does the same). The first build named `VOD_CLIENT_LOG`
    directly.
  - The G3 / G5 handler-replay suites execute the handler outside the module, and every request there answered 500
    `name 'VOD_CLIENT_LOG' is not defined`. That is 3 failures in `tests/session_identity` and 2 in
    `tests/wan_telemetry`, in the first full regression run.
  - Fixed before anything else; both suites green since. That first run's file was overwritten by the rerun;
    disclosed here.
- Under identity v2 the path needs the `diagnostics` permission on both sides already, default on for a paired device.

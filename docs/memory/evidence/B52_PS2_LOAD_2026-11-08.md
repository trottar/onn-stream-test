## 1. Settled (HOME-5's PCSX2 log, the hub's ini, the 2.8.2 binary)

- **Two causes, both removed.**
  1. **MTVU:** the hub's ini had `[EmuCore/Speedhacks] vuThread = true`, and PCSX2 warned at both loads: "MTVU speedhack
     is enabled, saved states may not be stable".
  2. **A load before the game had booted:** HOME-5's relaunch log has **no `ELF Loading:` line**. The start handoff
     paused PCSX2 at 2.0 s, and both loads went into a VM whose game had never started; the ten `TLB Miss` lines were
     identical at both (the same pcs and addresses).
  - PINE cannot say "the game is running": its 0x0C is `GetDiscSerial`, known from the disc's open during the BIOS. So
    the signal is PCSX2's own `ELF Loading:` line.
- **MTVU off for PrivyHub's PS2 sessions.** No reason was found to keep it (the hub has 6 cores / 12 threads).
  - **The expected cost, for A to measure:** VU1 (18-22 % of a core) moves onto the EE thread (mean 28-31 %, max
    62 %). That thread's mean should rise to ~50 %, its peak toward ~85-100 % of one core in a heavy scene. A heavy
    title may drop frames; a light one should not.
- **HOME-5's save is treated as unusable.** It was made with MTVU on, in a VM whose game never booted. It is kept on the
  hub (nothing deleted), and **the user makes a new save at HOME-6**; PCSX2 keeps the old file as `.p2s.backup`.
- **Kept:** `BackupSavestate` (a restore path) and fast boot.

## 2. Built

- **The ini per launch:** `[EmuCore/Speedhacks] vuThread = false`.
- **The load** (`_pcsx2_load_state`):
  1. PS1's preconditions and messages; the PINE hand-over (B51);
  2. **the ELF hold:** with no `ELF Loading:` yet in this launch's PCSX2 log, resume PCSX2, wait ≤ 30 s for the line,
     pause. Never seen → PS1-shaped error "The game is still starting; play a moment, then load again", paused;
  3. the pre-load picture (one 64×36 gray frame of the PID's window, hashed);
  4. PINE `0x0A` + slot, and PCSX2's `Loaded state from slot N.` (≤ 3 s);
  5. **resume, then the picture check** (every 0.2 s, ≤ 5 s): **ok** = 3 distinct frames, none the pre-load one, not all
     near-black, PINE running, no `TLB Miss` since the load; **fault** = a `TLB Miss`; **static** otherwise;
  6. **pause again**, so the game is left paused as PS1's load leaves it, having run the ~0.3-1 s the check took
     (disclosed);
  7. ok → the PS1 payload with `confirmed: true`, `verification: "picture"`; static / fault → **"The game did not
     resume from the save"** in PS1's error shape.
- **The game log:** `PS2 load: slot N pine 0x0a ok; picture <ok|static|fault> <s>s`.
- **Why the window and not the encoder:** at a Game State load the stream is stopped (the user is on the onn's game
  screen), so the encoder sends no frames. The window grab works with or without a stream.

## 0. Settled

**The sequence at C23's loss** (read in place: the recovery log, RetroArch's per-launch command log, T6's game log,
the host samples, A's capture):
- 22:33:23: a slot-0 save **into the paused core** (at the Back) is answered and logged; 22:33:32 is the last answered
  command (the resume).
- 22:35:28.2: the Home press. **≈22:35:29.39:** the stall's `SAVE_STATE_SLOT 9` **into the running core**.
  **22:35:29.42: the capture's last distinct frame.** From 22:35:29.9 to the stop, every `GET_STATUS` times out: the
  46 `stall_resume_failed`, then `SAVE_FILES` / `QUIT` unanswered, and RetroArch SIGTERMed (`forced`).
- **RetroArch never logged the slot-9 save** (a PS1 slot-9 save logs one). The trailing `plugin_start_gfx` is the
  core's buffered stdout, flushed at exit (T5's clean logs end with it too). There is no `Unloading game`.
- **RetroArch spun, it did not deadlock:** its CPU went 20.2 % → 92.1 % → 100 % of a core. The main loop sat inside
  the core and never polled its command port again.
- **Every N64 save that worked was into a paused core** (that 22:33:23 save; T5's SAVE / LOAD).

**The reproduction (B, headless, the hub's display, no stream, no pad, no title; `b61_2026-11-08/repro/`):**
- **The fixture:** a synthetic ROM (a header and a VI loop that flips the framebuffer each vertical interrupt;
  `fixture_rom.py`), on the hub's RetroArch and core, with temp config / state / save / XDG folders and a read-only
  copy of the hub's `.opt`.
- **Result:** three running saves were acknowledged in **23.6-24.4 ms**, with no silence longer than one 0.27-s poll;
  the paused save in 23.6 ms. **With an x11grab capture of the window running: 13.5-24.2 ms, the same.** So A's
  capture is not implicated, and a running save does not hang the core by itself.
- **The first fixture shows the mechanism:** a ROM that never swaps a frame kept RetroArch's main thread at 100 %
  inside the core, with the port silent for 25 s. RetroArch answers commands only between `retro_run`s.
- **Disclosed:**
  - the first two runs crashed at startup: the shell had no `DISPLAY`, so RetroArch fell back to KMS. One of them ran
    outside the tool sandbox, on the mistaken guess that the sandbox blocked the GPU; it changed nothing;
  - with `DISPLAY` / `XAUTHORITY` taken from the companion's environment, every run went as above;
  - RetroArch, ffmpeg and the fixture left nothing running.

## 1. Built (`b61_2026-11-08/b61.diff`, 6 files)

**Option 3 of the queue's three:**
- **Why:** an asynchronous save with a longer budget, or a `GET_STATUS` tolerant of the gap, cannot help when the
  port never comes back. Removing the one operation that preceded the hang can.
- **The pieces:**
  - **`EmulatorManager._n64_core`:** set by an N64 launch only (None otherwise; reset with the process);
  - **`rewind_cores.Cores.save`:** an N64 session sends no scratch save (silence or stall). One `state_save_skipped`
    row, `reason "n64: no save into a running core"`;
  - **`Cores.release`:** an N64 release is `rewind_skipped` `"n64: plain resume (no state)"`, then today's resume
    (`GET_STATUS` / `PAUSE_TOGGLE`);
  - **`_capture_slot0_state`** (the user's SAVE, the recovery save):
    - an N64 core reading `PLAYING` is paused first (`PAUSE_TOGGLE`, wait `PAUSED`), saved, then toggled back;
    - a probe row `n64_paused_for_save`;
    - a core that will not pause → the save refused, never sent running;
  - **`stall_signal.resume`** (N64 only, through the hold's rewinder):
    - after **3** "did not respond" failures in a row, one `command_port_silent` row (`fails`, `since_ms`, the
      process's state letter and CPU % over 0.2 s);
    - then **one try per 10 s**, each failure logged once with `backoff_s` and `skipped`;
    - a success resets it (`resumed … after_silent_fails`); a new process starts unbounded.
- **The cost, disclosed:** an N64 hold or stall no longer rewinds to the onset; the game resumes where it was paused
  (0.4-1.3 s unseen). PS1 / SNES / PS2 keep theirs.
- **A test file outside the item, disclosed:** `tests/n64_session` (B59's) asserts `_n64_core` set on an N64 launch
  and None on a SNES one.

  - PS1 → 43 tries and 43 rows, as today; no rewinder → today;
  - a new process → unbounded.
- **Absent:** a fresh manager's `_n64_core` None; a SNES launch leaves it None (B59's harness).
- **Mutations** (`tests_mutations.txt`): the save skip removed; the release skip removed; the capture's pause

# B99 — the live read (`PRIVYHUB_H7=1`) (2026-11-11)

**Why:** every H7 read so far was of a save the search itself used (H7-P1 … P3). The independent check — and what a
PrivyParty mini game needs — is the same read from the game while it is played on the stream. **Baseline:** HEAD
`6cb4663b`. **Design** hashed before code at 21:05:50Z (`b99_2026-11-11/design.sha256`), after the settle.

## Settled (synthetic fixtures, B61's form: RetroArch headless, the hub's AppImage and cores, temp folders, the companion's display; `settle/`)

Every command sent the companion's way: a fresh UDP socket per command, one answer from the command port.

| | SNES (snes9x; the fixture's frame counter) | PS1 (Beetle PSX HW; a word in the core's own memory that moves by 1 a frame — found by frame-advance: +30, +30) |
| --- | --- | --- |
| **frames in 60 s: no reads / a read every second / no reads / a read every second** | **3,603 / 3,600 / 3,603 / 3,600** | **3,603 / 3,601 / 3,603 / 3,600** |
| frames a second | 60.0 in every window (the no-read windows 60.05 s long, the read windows 60.00 s) | 60.0 in every window |
| a read's answer (GET_STATUS + READ_CORE_RAM; 240 commands per system) | median 16.3-16.6 ms, worst 17.5 ms | median 16.3-16.4 ms, worst 17.7 ms |
| answers lost or wrong | 0 | 0 |

- **A read once a second does not disturb the game's frames.** An answer takes one frame (RetroArch answers commands
  once a frame).
- **Paused:** a read answers (median 16.6 ms, worst 17.0 ms); the frame counter does not move.
- **Interleaved, 30 s running** (status every 0.1 s, a read every 0.25 s, a save every 3 s, the hold's pause every 4 s):
  status 260 / 260, reads 114 / 114, the hold's GET_STATUS 7 / 7 — each matched to its own command; **0 lost, 0
  crossed**. A command with its own socket cannot receive another's late answer (B93's crossing came from one socket
  shared by all commands).
- **N64** (B61's ROM): `READ_CORE_RAM` / `READ_CORE_MEMORY` (offset and 0x80… forms) answer in 15-17 ms. The fixture's
  RDRAM is all zeros (its code never lands in RDRAM — a 4 MiB dump; a store-program variant at ROM 0x1000 did not run
  either, `settle/fixture_n64_store.py`), so **no N64 byte order is anchored here**. What the route needs: an N64 rule's
  addresses and widths as the search found them through the same `READ_CORE_*` reads (B94: those reads are word-swapped
  against the core's own state file) — read back the same way. No N64 rule exists yet.

## Built (`b99.diff`)

- **`companion/h7_live_read.py`** (new), imported by `plugins/games.py` only with `PRIVYHUB_H7=1`; the route
  `GET /plugins/games/h7-read` added before today's "unknown action" answer.
- **No game** → 200 `{"ok": true, "running": false}`. **PS2 / GameCube sessions** → 400 "reading a PS2 game's memory is
  not supported yet" (… GameCube …); other systems than PS1, SNES, N64 → "not supported yet".
- **The rule:** `~/privyhub_h7/rules/<the hub's game id>.json` (`PRIVYHUB_H7_RULES` moves the folder); B93's rule JSON,
  checked as B93 checks it. Missing → 400 "no rule for this game"; malformed → 400 "the rule for this game cannot be
  read: …".
- **The read:** through `EmulatorManager._retroarch_network_request` (the companion's own command path and command log),
  **holding the manager's lock** (the save / load / launch / status lock) — waited for at most 0.3 s, else 502 "the game
  is busy (a save or a load); not read"; `GET_STATUS`, then one `READ_CORE_RAM` / `READ_CORE_MEMORY` per field, each
  with the time left, one try; **the whole read bounded at 0.6 s** → 502 "the game's memory did not answer in time; not
  read". Every answer must be its own command's (the word, the address, n bytes): `-1` → 502 "the game's memory has no
  address 0x…"; anything else → 502 "an unexpected answer from RetroArch; not read". Nothing retried in a loop.
- **The answer:** `{"ok": true, "game", "running": true, "paused", "values": {"P1": …}, "winner": "P1" | … | null,
  "reason": "no winner yet" | "tie" | null, "read_ms"}` (B93 / B95's reading).
- **It changes nothing:** only `GET_STATUS` and `READ_CORE_*` are sent.
- **The floor:** one read per 0.25 s; a sooner call → the last answer with `"cached": true` and `"age_ms"`.
- **The log:** one row per read sent (errors too) in `logs/games/h7_reads.jsonl` (git-ignored, with the other game logs).
- **Not a client call:** the route is the hub's own (A's watcher); `tests/client_contract` unchanged, green.
- **For A:** `b99-h7-live-read.conf` — the bench drop-in text (`Environment=PRIVYHUB_H7=1`), for H7-L1's sitting only.

## Disclosed

- The read takes the manager's lock for ~50 ms (three commands of one frame each); a status poll or a save arriving
  then waits that long. A save holding the lock longer than 0.3 s makes a read answer "busy" — never a wrong value.
- The hold's own pause path (`hold_rewind`) sends its commands on its own sockets without that lock; per-command
  sockets keep the answers apart (S4 above).
- The fixture's PS1 code does not run headless (B94); its per-frame word is the core's own (found by frame-advance, not
  the fixture's counter).
- RetroArch headless in the settle only (synthetic fixtures, B61's form); the tests use the fake. Counted: **0 at the end** (`ps`, 22:14Z, after every batch). Intermediate counts of 2 were one headless session (an AppImage's two processes) of the other item's batch running beside it from its own work copy (noted in `b99_2026-11-11/tests_x3.txt` and `tests_mutations.txt`).

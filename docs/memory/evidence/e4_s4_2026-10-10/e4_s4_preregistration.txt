   epg.py -- while the games plugin's recovery state is PLAYING / PAUSED_RECOVERING / PAUSED_SAVED, a forced grab (the
   refresh endpoint or the background warmer) is queued (one entry per channel) and answered with the cached guide
   marked "refresh_deferred": true (the marker the toolchain-preparing path already returns), "deferred_reason":
   "stream_live"; the EPG status gains "deferred" (pending, requests, drained ok / failed, cap_fired, last_drain).
   When the state leaves those (ENDED), the queue drains in order, one grab at a time. A running grab is not touched.
   A deferral older than 60 min runs anyway (cap_fired). tools/e1_suite.py: the E1-CONC cycle, when a refresh comes
   back deferred, records a "deferred" row and waits 5 s (E4-S1's median grab ~5 s) before the next instead of
   re-asking at once; with the flag, each run's teardown waits for the queue to drain (<= 600 s) and records it
   (pending at start, wall time, drained ok / failed, cap_fired, the drain's own record) and reads the guide after.
   The flag lives in e3_flag.conf for its runs only (removed + daemon-reload + restart at their teardown).

## Settled (the code, the keeper's and the stream's logs; nothing started)

1. **How `WindowPicture` picked its window** (HEAD): `xdotool search --onlyvisible --pid <the manager's process>`, the
   largest by `getwindowgeometry`, Pillow's X11 grab of that **screen rectangle** — **kept in `self._window` and found
   again only after a grab failed. A screen grab never fails, and `MiniGame` with its `WindowPicture` lives as long as
   the companion: the rectangle was never tied to the game's process.**
2. **Why T89's pictures were the whole desktop:** T88 ran first in the same companion in both H7-V5 (steps 12-15
   before 16) and H7-D1 (T88's two passes before T89's); **T88's window is the whole screen** (the keeper's log:
   (0, 0, 1920, 1080)), so T89's watches grabbed **T88's rectangle** — the 1920 × 1080 screen with T89's window inside.
   It was not a 1920 × 1080 window of T89's process: **the stream's own finder (the same search, the window owned by
   the process, the largest) found 960 × 720 in all 20 N64 stream sessions in its log**, and **HEAD's code in the test
   below grabs (0, 0, 1920, 1080) for a 960 × 720 game after a full-screen one** — H7-V5's fault reproduced.
3. **Why T89 is windowed and T88 full screen:** RetroArch runs windowed for every core (`video_fullscreen = "false"`,
   `video_windowed_fullscreen = "false"` in the hub's base config; nothing in the launch sizes or maximises a window);
   the window takes the core's picture size × RetroArch's scale — the N64 core **960 × 720**, T88's PS1 core the whole
   **1920 × 1080** (the PS1 core's windows in the stream's log: 879 × 720 or 1920 × 1080).
4. **What A's keeper took:** the largest visible window of class `retroarch`, **found again whenever RetroArch's pid
   changed** — T89 **(960, 384, 960, 720)** (its bottom 24 rows below the screen, which Pillow pads black), T88
   (0, 0, 1920, 1080). **H7-D1's desktop pictures cut by (960, 384, 960, 720) equal H7-C2's keeper pictures of the same
   screen: mean difference 0.0 grey levels** (moved 24-30 px: 38-40) — exactly the spec's area.
5. **What the onn's stream shows for T89 in a mini game:** the mini game's switch is the stream's own start for the
   title's process (`_switch_stream` → `native_stream.start(managed_process_id=<the title>)`) → `_select_capture_target`
   ("Whole-desktop capture is intentionally disabled": fail closed) → **the 960 × 720 window by its id**
   (`x11grab -window_id`), scaled into 1920 × 1080 with black bars at the sides. **The onn sees T89's game window,
   never the desktop** — no fault for PP-H4, nothing to fix in the stream.

## Built (`b129.diff`, `companion/h7_minigame.py`)

`WindowPicture`: **the largest visible window owned by the game's own process** (`xdotool search --onlyvisible --pid
P`, each window's `getwindowpid` = P — the stream's own check, ≥ 64 × 64, the largest), its `getwindowgeometry`
rectangle grabbed as before; **found again whenever the game's process changes** (the cache keyed by the pid), after any
failed grab, and at most every `REFIND_S` = 10 s; **no window owned by the process → "the picture was not read: the
game's window was not found" → the watcher's existing `picture_failed` row, no read** — never another process's
rectangle, never the desktop. T88: the same window as before. Flag absent: the module is not imported.
